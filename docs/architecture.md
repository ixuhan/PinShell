# 架构（草案 v0，待确认技术栈后冻结）

> 目标：轻量、快速、内存小。单进程、单主窗口、便携优先。
> 本文只定义**模块边界与契约**，不含具体代码。

## 0. 总体形态

```
┌───────────────────────────── WebView2（前端） ─────────────────────────────┐
│  项目栏  │  终端视图(xterm.js) + 输入条  │  功能栏：快捷指令 / 串口列表 / 文件 │
└───────────────────────────────┬────────────────────────────────────────────┘
                        IPC（命令 + 事件流）
┌───────────────────────────────┴────────────────────────────────────────────┐
│                         Rust 核心（单进程，多线程）                          │
│  session-runtime  ──  transport(pty | serial)                               │
│       │                    │                                                │
│       ├── input-engine     ├── integration（OSC 解析 + 脚本生成）            │
│       ├── persistence      └── panels（fs / serial 枚举 / 原生菜单 helper）   │
│       └── core-domain（纯数据，无 IO）                                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

选择单进程的理由：会话之间本来就要共享历史库与设置；进程隔离换来的是「崩溃时全都活下来」，但代价是跨进程转发每一帧字节。**唯一例外是原生右键菜单的 shell 扩展**——第三方 DLL 会崩，必须放 helper 进程。

## 1. 模块与职责

| 模块 | 职责 | 允许依赖 |
|---|---|---|
| `core-domain` | 纯数据与规则：会话、传输类型、命令片段、快照结构、时间戳策略、状态枚举 | 无（只有标准库） |
| `transport` | `Transport` 抽象 + 两个实现：ConPTY 终端、串口。负责字节进出、resize、端口/DTR 控制、关闭语义 | core-domain |
| `session-runtime` | 会话生命周期状态机（冷 → 启动中 → 热 → 暂停/关闭）、回放缓冲、订阅管理、输入注入 | core-domain, transport |
| `integration` | 生成并注入集成脚本；解析会话回传的标记，驱动「提示符就绪 / 运行中 / 备用屏 / 未知」状态机；上报 CWD | core-domain |
| `input-engine` | 输入条的服务端：历史写入与检索、前缀预测、检索与排序、命令片段的「填充/发送」 | core-domain, persistence |
| `persistence` | 设置、工作区快照、历史库、卷轴快照的读写；原子落盘；便携目录探测与回退 | core-domain |
| `panels` | 文件面板（跟随 CWD / 固定路径、排序、刷新策略）、串口枚举与只读串口列表、原生右键菜单 helper | core-domain, persistence |
| `ui` | 前端：渲染、键位、焦点、布局、设置页 | 只经 IPC 调核心 |

依赖方向单向：`ui → session-runtime / input-engine / panels → transport / persistence → core-domain`。**禁止** UI 直接触 `transport`，也禁止 `transport` 反向依赖 `session-runtime`。

已落成代码的边界：`src-tauri/core-domain/` 是独立 crate（零依赖、自带测试、可用独立 target 目录编译），终端集成脚本在 `scripts/integration/pinshell.ps1`。项目分格模型在 `core-domain/workspace.rs`（项目、二叉分格树、会话元数据与结构校验，见 ADR 0006）；数据目录与原子写在 `src-tauri/src/persistence.rs`，JSON DTO 留在这一层，core-domain 保持零依赖。

## 2. 三个核心契约

### 2.1 Transport

```
trait Transport {
    fn write(bytes)
    fn resize(cols, rows)          // 串口为 no-op
    fn pause() / resume()          // 串口：真释放 / 重开
    fn close()
    fn capabilities() -> { completion, history, timestamp, alt_screen }
}
```

能力位决定 UI 行为：串口通道关掉输入条的命令历史/预测/补全，但保留发送历史与时间戳。

已落地（M5）：通道抽象收在 `src-tauri/src/transport.rs`。`Transport` 负责字节进出、resize、释放/重开、关闭、能力位、读端与日志；`PtyTransport` 与 `SerialTransport` 是仅有的两个实现，会话层（`main.rs`）不再直接认识 ConPTY 或 COM 口。原来散在会话层的「相同尺寸不下发」也随之下沉到 `PtyTransport`（`core_domain::resize::SentSize`），串口的 `resize` 是 no-op。

串口的几个约定：

- **暂停 = 真释放**。`release()` 先置停止位、丢掉写句柄，再把克隆给读线程的句柄 `join` 掉（Windows 上串口是独占打开，不 join 等于端口还被占着）；`reopen()` 按同一份配置重开。会话仍是热的：回放、历史、标题都不动，只是端口让给了别的程序。I4 因此按「热会话」判定，暂停中的会话仍占着它的端口名额。
- **失败可重连**。设备拔掉或读写报错时读线程结束，会话保持热、状态标为 `failed`；「连接」会先丢掉已经不可信的旧句柄再重开，而不是只把状态改回 `open`。
- **没有 Shell 就没有标记**。串口读线程不喂 OSC 解析器，字节经 `Utf8Stream` 解码后直接进回放与 `pty:out`，同时按原始字节写日志。输出静默 3 秒落卷轴快照、暂停继续整屏重画、清屏只清显示层这些规则与终端完全共用。
- **HEX 与行结束符**只有一处实现（`core_domain::serial`）：HEX 按整行解析成字节、**不追加**行结束符；行缓冲模式追加该会话的 CRLF / CR / LF；直发模式只写文本本身。
- **日志**落在 `data/logs/serial-<端口>-<UTC 时间>-<会话 id 前 8 位>.log`，按 `[RX/TX +毫秒]` 记，控制与高位字节转义成 `\r` / `\n` / `\xNN`，二进制里的换行不会把一条记录拆成两行。路径随 `serial:status` 给前端，「日志」按钮用系统关联打开。
- **假串口**：`PINSHELL_FAKE_SERIAL=1` 时端口列表多一个 `PINSHELL_LOOP`，它是内存回环（写什么回什么），完全不碰系统端口，没接硬件也能把界面走通。
- **落盘**：`workspace.json` 升到 v4，会话的 `owner` 变成必填（项目是唯一容器，ADR 0008）。v3 及更早的文件照常读：缺的 `serial` 按「没有串口配置」、缺的 `projects` 按空列表、旧 `windows` 直接忽略；`owner` 缺失或为空的会话在加载时丢弃（独立会话已不存在，不做迁移）。前端不复制默认值与校验，错误原文来自核心。

前端（M5）：新建会话只有一条入口——项目行的「＋」打开统一的新建会话弹窗（ADR 0008）：先选传输方式，终端填 shell profile 与起始目录，串口填端口（可手输，也可从 `serial_ports` 挑）与 8N1 参数，最后选落点。参数随工作区落盘、冷会话按它重连。串口会话在输入条上把「暂停」显示成「断开 / 连接」，并给出 `串口 COM3 · 115200 8N1` 摘要、错误原因、HEX 开关与日志入口；没有补全与 Ctrl+R，↑↓ 仍翻发送历史。串口列表在功能栏且只读。

### 2.2 输出事件

会话输出统一为「带时间戳的字节块」事件，附带该块是否改变了备用屏状态。前端永远只订阅事件，不直接读管道。

- 订阅先于连接：会话启动时后端立刻开始录制到回放缓冲，前端 attach 时先重放缓冲、再接实时流。
- 前端 detach（切走、窗口最小化）不影响录制。

已落地（M2 第一片）：回放缓冲在 `core-domain/src/replay.rs`（按字节上限裁掉最旧的**整块**，不切转义序列）；`pty:out` 带会话内递增的 `seq`，前端附着时先取 `pty_replay` 快照，再用 `seq` 去重补上附着期间到达的实时块。页面重载因此不再结束会话——启动时用 `pty_list` 决定「挂回」还是「新开」，只有窗口关闭才结束全部进程（I3）。

已落地（M2 第二片）：会话树（`session_tree` 含冷会话，行上的 `hot` 对照 `pty_list` 里的活会话），以及 **CWD 跟随**——Shell 每次提示符上报的 `OSC 7` 写进会话元数据 `cwd`，冷会话重新拉起时用它做启动目录；目录已不存在就让 spawn 失败、前端退回默认目录重试一次。落盘规则只有一条：`Workspace::set_cwd` 返回「真的变了」才写 `workspace.json`，否则每个回车都会重写一遍文件。

已落地（M2 第三片）：**卷轴快照**。会话结束（进程退出）与应用退出时，把该会话回放缓冲里的内容写成 `scrollback/<id>.ansi`；输出静默 3 秒后也补写一次（连续刷屏时不写，崩溃退出最多丢最后几秒）。冷会话重新拉起时先读回这份快照、经 `core_domain::scrollback::compose` 接上一条分隔线后作为回放缓冲的第一块，于是屏幕不再是空的。组装时丢掉备用屏与隐藏光标开关、末尾复位 SGR 并放出光标，免得快照里 vim/less 的终端模式带到新会话。快照只用于显示，不进命令历史，也不参与所有权判定（分隔线里刻意不含任何 `133` / `7` 标记）。关闭会话按 I2 删除快照；覆盖写不保留 `.bak`（显示层没有救回上一版的必要）。热会话还可以手动**冻结**（右键 → 冻结会话，`pty_freeze`）：写快照、结束进程/端口、把 `hot` 置回 false，但保留工作区节点、命令历史与快照，点该行时按原参数重新拉起；与「删除」的区别是它只结束运行时，不销毁记录。应用退出时同时把所有会话标成冷再落盘，下次启动不会读到一堆 `hot`。

会话标题可改（侧栏双击名字就地编辑，回车提交、Esc 放弃）：规则只有「去首尾空白、按字符截断到 40、全空白拒绝」三条，放在 `Workspace::rename_session`；冷会话重新拉起不覆盖用户改过的名字。

已落地（M3 打磨）：**暂停接收输出**与**一键清窗口**都是显示层动作，都不碰命令历史与进程。

- **暂停**由后端记账（`pty_set_paused` / `pty_paused`）：读线程照常解析、照常写回放缓冲，只是不再发 `pty:out`——刷屏时省掉的是 IPC 与前端渲染，不是数据。继续时前端先 `term.reset()` 再按 `pty_replay` 整屏重画，而不是把增量接在旧屏幕后面：Shell 心里只有它自己那块屏幕，增量对接会错行。暂停期间攒在合流缓冲里的块直接丢掉（内容在回放里，再发一遍等于画两次），所以暂停多久都不会把内存堆起来；暂停时合流缓冲还另有 1MB 上限兜底（`push_capped`，超限整块让位）：正常情况下发送线程每帧取走并丢弃，缓冲只有几 KB，这个上限只在发送线程失效时防止内存无界增长。回放缓冲自己按字节上限整块裁旧，暂停太久只保住最近一段。暂停是会话级状态、由后端持有，切走再切回来按 `pty_paused` 复原按钮，不靠前端记忆。
- **整屏重画的顺序**（切会话 / 继续 / 重新附着共用 `resyncScreen`）：先按当前布局 `fit`，再写快照——写完再 fit 会在解析途中触发重排，底部提示符与滚动位置都会被推走；回放解析完把视口贴回底部并整屏 `refresh`——浏览器里滚动条高度的变化是异步派发的，不补这一步时视口可能停在历史的半屏上，画面看起来整体上移，而实际输入位置仍在缓冲区末尾。WebGL 只重画变脏的行，所以整屏刷一次也是把画布与模型对齐的必要步骤。
- **清窗口** = `pty_clear`：清后端回放缓冲、删磁盘上的卷轴快照（重开应用也不会再把旧内容画回来）、前端 `term.clear()`（与 `clear` 指令一致，当前行提到首行、历史一起丢）。清空的只是**历史**：光标那一行（通常就是提示符）留在回放缓冲的最前面，所以切走再切回来、或「暂停 → 继续」整屏重画时，那一行还在——否则屏幕上只剩一个光标，看着像会话死了。它返回清空前的最后序号，前端把序号不大于它的块丢掉——清屏那一刻已经在 IPC 路上、或已排进帧队列的旧输出，不会冒到空屏上。**不发 `Ctrl+L`**：跑着 `adb logcat` 这类前台进程时，那等于往它的 stdin 塞控制字符。代价是 Shell 仍以为屏幕上有内容，全屏程序（vim / less）要它们自己的重画键。

已按临时数据目录（`PINSHELL_DATA_DIR`）手工走通一遍 M2 验收链路：首次运行从 `OSC 7` 记下 CWD；关闭窗口写出快照并留下 `hot: false`；重启后读回 1 个冷会话、按记住的 CWD 重新拉起；再关一次后快照里正好多出一条分隔线，说明上次屏幕确实被接在了新会话前面。

### 2.3 输入

输入条只有两条出口：

- **填充**：把文本放回输入条（命令片段的填充模式）。
- **发送**：`text + 行结束符` 写入 Transport；发送后写入历史、清空输入条、状态由 integration 推进。（落盘与去重见 M3，已落地。）

直通模式下的按键走另一条路径，不做任何文本处理，直接 `write` 原始字节。

已落地（M5）：`pty_send_line` 多一个可选的 `hex`。终端与串口的区别只在组包：终端固定 `text + \r`；串口按该会话的 `send_mode` 与 `line_ending` 组包，`hex = true` 时把整行按十六进制解析成字节、原样写出（不追加结束符）。解析拒绝原因（空、奇数位、非法字符及其位置）由 `core_domain::serial` 给出，界面直接显示原文。端口断开或读写失败时发送返回错误，前端把这一行放回输入条，不让用户重敲。

已落地（M3）：历史按 `session_id` 隔离，只记输入条提交的行；直通键入、片段发送、REPL 输入都不记。同一条命令只留一行，再次执行时挪到最新并累加次数；去重键是原文。每会话封顶 10000 条。`history.db` 用 SQLite（WAL、单写线程），先发 PTY、再异步写库；落盘失败只挂一次「历史未保存」标记，本次运行退化为纯内存。条目存原文、UTC 毫秒、执行次数、最后使用时间，不记 CWD 与退出码。库打不开或损坏时改名为 `history.db.corrupt-<时间>` 并重建空库，不阻塞启动。清空历史只作用于当前会话；删除会话节点连同历史一起销毁。前端缓存契约：附着取 `history_snapshot`（最近 5000 条，带 `upto_id`），随后收带单调 `id` 的 `history:append`；检测到缺口或重连就整份重建，不逐条修补，缓存只留当前焦点会话。

实现备注：`rev`（对外叫 `id`）是会话内的「第几次提交」，由 `history_meta.next_rev` 发号，删除/清空都不会让号回退，因此 `history:append` 的 `id` 严格 +1，前端按缺口重建的规则才成立。写线程 `history` 串行处理全部写与读，读走同一个线程（快照 5k 行、检索 10k 行都在毫秒级），避免写锁和读锁互相拖慢。规则在 `core-domain/src/history.rs`（`Log` 内存模型 + `search` + `local_day`/`day_anchors`），落盘在 `src-tauri/src/history.rs`。

判定结果由核心推送 `pty:ownership { id, owner, confidence, state, override }`，只在变化时发一帧；前端不复制判定规则，只按结果在「输入条」与「终端」之间搬动焦点。按键路径因此没有任何逐键 IPC，规则也只有一处实现。

### 2.4 功能栏与文件面板

右栏是**功能栏**（ADR 0007）：快捷指令、串口列表、文件三个面板完全同权——各自记住高度、可折叠、可隐藏、可排序，最后一个「可见且展开」的面板吃剩余高度（`rb-fill`，此时高度手柄隐藏）。可见性与顺序是一份窗口级布局，存 `localStorage` 的 `pinshell.rightbar`，在全局设置里勾选与 `↑↓` 调整即生效；三个全不勾时整条功能栏消失，标题栏的折叠按钮置灰。挂到 `#files` 上的 `no-panels` 负责这一步；面板被隐藏时不渲染、不占高，并停止自己的后台刷新（串口轮询 / 文件自动刷新）。纯逻辑在 `src/rightBar.ts`（可见性、顺序、谁吃剩余高度、高度夹取），DOM 装配在 `src/rightBarUi.ts`。

面板是**窗口级 UI**，显示**焦点会话**的 CWD（ADR 0004），只有「跟随 / 固定」两种模式：跟随时路径由会话的 `OSC 7` 决定；手动导航（双击进入子目录、上一级）即转成固定路径，否则 Shell 每 `cd` 一次就会把用户正在看的目录拽走。**面板内容**跟焦点会话走，但「跟随 / 固定」「自动」「隐」这三项是**会话级设置**：每个会话各存一套，切会话时整套换掉，A 会话停在固定路径、开着自动刷新、显示隐藏项，B 会话仍然可以是跟随、手动刷新、隐藏隐藏项。面板宽度与展开状态属于窗口布局，不随会话变化。

已落地（M4 第一片）：**只读目录服务**。`fs_list` 接三个可选参数：`path` 为空时按 `session` 记下的 `cwd` 取，两者都没有回退用户主目录；读盘放阻塞线程池，网络盘慢也不堵 IPC。条目模型与显示规则在 `core-domain/src/fsview.rs`（目录优先、名字大小写不敏感排序、隐藏项计数、2000 条截断、`normalize`/`parent_of`/`child_of`），`src-tauri/src/fsview.rs` 只负责把 `std::fs` 的元数据填进结构体（跟随链接判类型、Windows 隐藏属性、取不到时间留空）。CWD 真变化时后端推 `session:cwd`，面板只在跟随模式下据此重画。

面板的列表顶部固定一行 `..`（父目录那一行）：双击回退一级，和头部 ↑ 走同一条 `enter`；它没有大小与时间、颜色压暗一档，不参与排序与「N 项」计数，没有父目录（盘符根、UNC 根）时整行不出现。

两条刻意的取舍：归一化**不折 `..`**，因为面板的导航只走父子关系，显示路径与系统解析必须一致；非 UTF-8 文件名用有损转换只做展示，面板不写磁盘。前端只放格式与模式选择（大小分档、当天/同年/跨年时间、路径拼接、该请求哪个目录），在 `src/filePanel.ts`，由 vitest 覆盖。

自动刷新（M4 第二片）默认**关**，点「自动」才开。它与「跟随 / 固定」「隐」一起作为**会话级偏好**存在 `localStorage` 的 `pinshell.files` 里：`sessions[会话 id]` 各一套，另有 `defaults` 给还没有自己记录的会话（旧版把三项放在顶层的全局配置也迁移到这里，老用户不会被重置）。切会话时先把上一个会话的当前状态写回去，再换上新的；新建会话沿用最近一次用过的设置，但不继承固定路径，从自己的 CWD 起步。周期用递归 `setTimeout` 排：上一次回来之后再等一个周期，慢盘或网络盘上不会把请求堆起来。只有面板展开、有焦点会话、页面可见、且没在拖宽度时才排期；窗口被遮住就停，回到前台先补一次。

代价按「目录条目数」线性上涨（本机实测：读盘约 0.08ms/条，DOM 重建约 0.11ms/行，IPC+JSON 可忽略），所以：

- 普通目录 1 秒一次（与串口面板同一节拍）；`total` 超过 1000 的目录自动放慢到 10 秒，按钮提示里直接写明当前周期。
- 读盘失败按 2 的幂退避（1 秒起步），最多 24 秒，别对断开的网络盘每秒重试一次。
- 结果先与上一份逐项比较（路径/父路径/总数/隐藏数/截断标记 + 每条的 name/kind/link/size/modified_ms/顺序），完全一样就**什么都不做**；只有真变了才重绘，并在同一目录重绘时保住 `scrollTop`、按名字恢复选中行。这条比省 CPU 更要紧：否则每秒一次会把用户翻到的位置踢回开头、把点中的行清掉。

面板宽度可拖动（140–560px，双击分隔条恢复默认）。拖动中只改 CSS 宽度，终端保持原尺寸、由 `#term-host` 裁掉多出来的部分——拖动中每跨一列就重排一次会让会话区不停闪；松手后才 fit 一次并把新尺寸下给 PTY。左栏（项目栏）用同一套手势（`src/resize.ts`，150–360px，双击恢复默认），两栏各自量对方的实时宽度来决定自己的上限，所以拖宽一栏不会把终端挤到 180px 以下。两栏都能收起成 26px 的竖条：项目栏收起后是竖排「项目」的展开按钮加一个齿轮（全局设置入口），功能栏收起后是一条竖排「功能」的展开按钮；收起状态与宽度一起存进 `localStorage`，重开还是原样，收起时拖拽手柄隐藏、宽度原值保留，展开时先按当前窗口重新夹一遍。项目行自身的展开/收起（`expanded` 集合）与「全部收起 / 全部展开」按钮是另一套，收的是项目行不是整栏。三个功能面板各自的高度也用同一套 `dragHeight`（下限 120px、上限为可用高度的 70%），排在最后的那一个由 flex 决定高度、手柄隐藏。拖高时传的是面板自己（`#files-panel` / `#ports-panel` / `#shortcuts-panel`），可用空间与邻居高度都按 `#files-body` 里的兄弟面板算——传成整条功能栏（`#files`）会把 `#app` 的兄弟当成邻居，夹取结果恒为下限、拖不动。文件面板的下限还会抬到「标题栏 + 操作行 + 路径栏 + 刷新行 + 页脚」的高度（宽度变窄让操作行换行时随之变大），因为矮于这些固定行时列表已经没有空间。任何面板被挤得比自己的固定行还矮（窗口变小、最后的撑满面板被压扁）时，`.panel-body` 的 `overflow: hidden` 把多出来的内容裁掉，不会画到下一个面板上——那看起来就是两个面板「重叠」。其它布局变化（拖窗口、折叠面板、改另一栏的宽度）由 `#term-host` 上的 `ResizeObserver` 负责：它在布局后、绘制前触发，而 WebGL 画布是独立合成层，晚一帧就会把旧尺寸画到面板上。窗口变窄时两栏已保存的宽度都会被重新夹到合法区间。诊断 HUD 相对 `#main` 定位并单行截断，不覆盖面板与输入条；`#main` / `#term-host` 裁剪溢出（再加 `clip-path`），窗口或面板缩放时画布不会画到邻居上。

右键菜单（M4 第三片）走**原生菜单 + 降级**两条路。列表行（含顶部 `..`）右键后调 `fs_context_menu(path)`，列表空白处右键调 `fs_context_menu(path, background=true)`：前者是条目菜单，后者是目录自己的背景菜单（`IShellFolder::CreateViewObject` 请求 `IContextMenu`，与资源管理器右键空白处同源，含新建 / 粘贴 / 属性）。主进程起同目录的 `pinshell-shellmenu.exe` helper；helper 用系统 Shell 的 `IContextMenu`（`SHParseDisplayName`，条目菜单再 `SHBindToParent` → `GetUIObjectOf`，背景菜单 `SHGetDesktopFolder` → `BindToObject` → `CreateViewObject`，然后 `QueryContextMenu` → `TrackPopupMenuEx` → `InvokeCommand`）弹出真正的资源管理器菜单，所以 7-Zip、TortoiseGit 之类的扩展都在。菜单坐标取鼠标当前位置，不做 DPI 换算。

helper 必须是独立进程：第三方 shell 扩展以 DLL 注入宿主，崩了会带走宿主。主进程只等退出码与一行 stdout（`handled` / `cancelled`），上限 10 分钟；找不到 helper、启动失败、非零退出或超时都返回 `unavailable`，前端改用自建菜单（打开 / 在资源管理器中显示 / 复制路径 / 填入输入条），不弹错误框、不丢会话。自建菜单的项集合与位置夹取是纯函数（`rowMenu` / `clampMenuPosition`），由 vitest 覆盖；菜单打开期间自动刷新暂停，列表重建、窗口失焦、滚动或 `Esc` 都会关掉它，不在重建后指向一行已经不存在的条目。

`fs_open` / `fs_reveal` 是两条路共用的动作出口，都交给系统关联（`explorer.exe`），应用内不维护扩展名表。helper 与主程序同目录（开发期 `target/debug`，运行时先看 `PINSHELL_SHELLMENU`）。安装版不声明 `bundle.externalBin`：tauri-cli 2.12 起会把应用 crate 的每个 `[[bin]]` 当作 sidecar 打进安装包，再声明 externalBin 就是同一个文件装两遍，WiX 以 ICE30 拒绝链接（本机实测，MSI 直接构建失败）。因此 helper 只是一个普通 `[[bin]]`，`app:build` 时随 crate 一起编译，MSI 与 NSIS 各装一份到安装目录、与主程序同级。helper 的 `--probe` 只跑到 `QueryContextMenu` 就退出，用来验证 COM 链路而不弹菜单（`--background` 时验证的是背景菜单，`F:\PinShell` 上实测 10 项）。开发期由 `npm run app:dev` 先跑 `cargo build --bin pinshell-shellmenu` 把它送到 `target/debug`，否则右键永远走降级菜单；`Cargo.toml` 里的 `default-run = "pinshell"` 则保证有两个可执行文件时 `cargo run` 仍然知道该起哪个。

列表空白处点一下会让列表自己拿到焦点，之后 `F5` 重读当前目录；焦点在终端时 `F5` 照常发给 Shell。路径栏是可点的面包屑：单击某一级进入该目录，`✎`（或双击路径栏空白处）切成输入框，回车跳转、`Esc` 或失焦还原。两者都不在列表重建时丢状态：面包屑由当前路径重画，输入中的文本框由用户提交后才被替换。

## 3. 状态机（会话）

```
Cold ──启动──► Spawning ──首个提示符──► Live
Live ──关闭──► Closing ──► Cold(保留元数据+历史) | Deleted
Live ──串口暂停──► Paused ──恢复──► Live
```

`Paused` 只指**串口暂停**（M5，真正释放串口）。**输出暂停**（M3 打磨）是显示层开关，不改变会话状态：会话仍是 `Live`，进程照跑、回放照记，只是不再往前端推。

不变量：

- **I1** 冷会话没有进程。
- **I2** 关格 = 写卷轴快照、结束运行时、节点留在原位、历史与快照都保留（`pty_freeze`）；移除格 = 摘除节点，连同该会话的历史与卷轴快照一起销毁（`pty_close`，界面上的移除入口要二次确认并写明）；进程自然退出等同关格：写快照、标冷、节点留着。侧栏的 × 与批量删除走「移除格」，两个动词不要混用。
- **I3** 退出应用 = 结束全部进程，不做保活；还原完全依赖快照。
- **I4** 同一串口不允许两个热会话。
- **I5** 一键清窗口只清显示层与回放缓冲，不触碰历史库。

## 4. 输入归属（最关键的判定）

**输入所有权**是唯一决定按键去向的规则，判定方式按通道类型而定：

- **终端通道**：备用屏 > 提示符就绪 > 未知。只有提示符就绪允许输入条接管；未知与猜测状态下输入条仍可显示，但按键全透传（只做建议），用户可用快捷键显式锁定。UI 必须能区分「确知就绪」与「猜测」——状态点放在输入条左侧。
- **串口通道**：所有权恒归输入条，因为没有第二个进程消费按键；不存在「提示符就绪」这个概念。串口输入另有「直发 / 行缓冲」两种方式（设置项，非会话类型），HEX 发送一律按整行组包。

任何新的通道类型都必须回答同一个问题：「谁在跟输入条抢按键」，而不是复述终端的状态机。

**焦点策略**：所有权是后端的裁定，前端只负责搬运——`owner = input_bar` 时焦点在输入条，否则在终端；只在两者之间搬动，不抢其它控件。用户的显式覆盖（`Ctrl+Shift+P` 锁直通、`Ctrl+Shift+L` 锁输入条）同样由后端记账，前端只是发一个意图。输入条右侧的「暂停 / 清屏 / 直通 / 接管」四个按钮与快捷键走同一条路径，鼠标点得到；按钮一律不抢焦点（`mousedown` 阻止默认），点完接着敲键盘即可。

## 5. 数据目录

```
data/                     ← 便携：exe 同级；不可写则回退 %APPDATA%\PinShell\
├── settings.json         ← 即时生效，热重载
├── workspace.json        ← 项目/会话/分格布局/片段；+ workspace.json.bak
├── history.db            ← SQLite，按 session_id 隔离
├── scrollback/<id>.ansi  ← 卷轴快照；空闲 3 秒落盘
├── logs/                 ← 串口日志 serial-<端口>-<UTC>-<会话 id 前 8 位>.log（RX/TX + 毫秒）
└── integration/          ← 生成的 Shell 脚本副本（用于注入与版本比对）
```

`history.db` 明文保存输入条提交的命令；当前版本不识别敏感内容，不要在输入条输入密钥。误贴后唯一的补救是「清空本会话历史」。

原子写：同目录 tmp → `FlushFileBuffers` → `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)`，失败退避重试；保留上一版 `.bak`。Windows 无目录 fsync，不照搬 POSIX。

已落地（M2）：目录解析顺序 `PINSHELL_DATA_DIR`（明确指定却不可写就报错，不悄悄换地方）→ exe 同级 `data\` → `%APPDATA%\PinShell\`；`workspace.json` 带 `version`（M2 时为 1，M5 升到 2，项目功能升到 3，ADR 0008 升到 4），读回后一律按冷会话处理。写入失败不会留下半截主文件，读取时主文件坏了自动退 `.bak`，两份都坏返回 `Unreadable` 而不是静默重置。卷轴快照已落成 `scrollback/<id>.ansi`（纯文本、覆盖写、不保留 `.bak`；替换时旧版先挪到 `.old`，失败再挪回来，成功后删掉；文件名由会话 id 派生，非法 id 一律换成定长哈希名，防止写到数据目录外面）。

已落地（M3）：`history.db` 由 `src-tauri/src/history.rs` 持有，WAL + `synchronous=NORMAL` + `busy_timeout`；表 `history(session_id, rev, command, used_ms, use_count)` 与 `history_meta(session_id, next_rev)`。打开时跑 `PRAGMA quick_check`，失败则把主库连同 `-wal`/`-shm` 改名成 `history.db.corrupt-<UTC 毫秒>` 后重建空库；重建也失败就本次运行只用内存，并只发一次 `history:degraded`（前端只提示「历史未保存」，不挡输入）。日志仍随 M5 落地。

## 6. 前端职责边界

前端**不做**：历史写入、检索排序、时间戳插入、卷轴序列化的决策。它只做渲染与交互，把「按了什么键 / 点了什么」变成意图发给核心，把核心返回的结果画出来。

**唯一例外（性能豁免）**：前端持有当前会话历史的**只读热缓存**（最近约 5000 条，纯内存、不可写），用于逐键的 Ghost Text 前缀匹配，避免每次按键都跨进程。缓存由核心在历史变更时增量推送；写入、去重、深度检索仍只在核心发生。缓存与库不一致时以库为准，重连即重建。

理由：业务逻辑一旦分叉两处，还原行为就会不一致；但让打字手感挂在 IPC 上不值得。这条例外的边界是「只读、只能读当前会话、只能读最近窗口」。

已落地（M3）：Ghost Text 只在光标位于行尾、输入非空白且为单行时出现，对最近 5000 条做大小写不敏感的前缀匹配，最近优先，`→` 接受整条建议；多行条目不参与。Ctrl+R 是输入条上方覆盖层，`Esc` 关闭并恢复打开前的草稿，`Enter` 只填充不发送；大小写不敏感子串匹配，查询含大写转敏感，按最后使用时间倒序；先本地过滤 5000 条，40 ms 防抖后向核心查全量并标出更早的记录（`更早` 标记按「不在本地缓存里」判断）。`↑` 只翻 5000 条。时间戳存 UTC，跨天按当前本地时区渲染，锚点是 Ctrl+R 列表里的日期分隔行。纯规则在 `src/history.ts`（`ghostFor` / `filterHistory` / `withDayAnchors`），由 vitest 覆盖 L0-07 与 L0-09。缓存契约单独抽在 `src/historyCache.ts`（`emptyCache` / `fromSnapshot` / `applyAppend`）：切会话先整份丢弃，再按快照的 `upto_id` 重建；追加只认当前会话、只认 `id` 正好 +1，跳号整份重建而不是逐条修补；同一条命令再次提交时摘掉旧行挪到最新，窗口超过 5000 条挤掉最旧的。由 vitest 覆盖 L2-02，门禁里与 L0 同批跑。

**实测依据**：Tauri IPC 往返 p50 ≈ 1.8ms、p99 ≈ 4.3ms（见 `docs/bench-m0.md`）。对一帧 16.7ms 的输入来说是可感知的，所以按键路径一律「先本地回显、异步写 PTY」，且不得 `await`。

**卷轴行数上限**：xterm 的 `scrollback` 取 5000 行。上限的理由是**内存**与持续裁剪的成本，不是渲染——WebGL 只画视口那几十行。实测（120 列、Node 里只解析不渲染、8 MB / 129k 行、每个上限单独起进程）：1000 / 5000 / 10000 / 50000 行的稳态吞吐都在 58 MB/s 上下（灌满那段 130–230 ms，上限越大越慢），而留住的缓冲按每行约 0.4 KB 线性增长——5000 行 2.0 MB、10000 行 3.8 MB、50000 行 18.5 MB。对照其他产品的默认值：VS Code 1000、tmux / kitty 2000、WezTerm 3500、Windows Terminal 9001、Alacritty 10000、iTerm2 默认不限。取 5000 是「比 VS Code 默认多看 5 倍、单会话约 2 MB」的折中，改这个数只影响内存占用，不影响稳态吞吐。数字与复现方法见 `docs/bench-m0.md`。

## 8. 已知取舍（会在 ADR 里逐条记）

1. 补全只做「统一浅补全」，放弃 shell 原生补全对等。
2. 会话是通道，不是 shell 进程——串口因此能进同一套模型。
