# 查找（Find）规格 v0

> 定义见 `GLOSSARY.md`。本文补充行为规则与落点，供实现用。

## 一句话定义

**在焦点分格已经画出来的内容里定位一个字符串，命中高亮、可在命中之间前后跳转。**

它是只读操作：不修改屏幕、不产生发送内容、不写命令历史。数据源只有前端 xterm 的缓冲区，触及不到磁盘上的任何副本（见 ADR 0009）。

## 不做什么（边界）

1. **不查命令历史。** 历史归「检索」（`Ctrl+R`），数据源是 `history.db`，两者不重叠。
2. **不查磁盘。** 不读 `scrollback/<id>.ansi`，不读会话日志，也不读串口诊断日志。
3. **不跨会话、不跨分格。** 一次查找只作用于一个分格的一个屏幕。
4. **不用正则，不跨行匹配。** 匹配单位是屏幕上的逻辑行；xterm 的折行由插件处理，视觉上命中可能跨两行，但语义仍是行内子串。
5. **冷格不提供入口。** 冷会话是纯 DOM 占位（`.pane-cold`），没有 Terminal 实例，也就没有可查找的屏幕；要搜它得先拉起（那时快照已经被回放进缓冲区，可以搜）。
6. **不产生副作用。** 不写历史、不改 CWD、不触发集成脚本、不改变通道状态。

## 入口与键位

- **`Ctrl+Shift+F` 是唯一入口，任何时候都截获**——包括直通模式和备用屏。
- **`Ctrl+F` 永远不截获**，原样交给通道。bash readline 的 `forward-char` 与 PSReadLine 的 `ForwardWord` 都绑在它上面，抢走它会打断 Shell 的行编辑。`Ctrl+F` 唯一的风险来自 WebView2 的浏览器加速键，而后端已经 `SetAreBrowserAcceleratorKeysEnabled(false)`。
- 再按一次 `Ctrl+Shift+F` 关闭；`Esc` 也关闭。
- 这是 `src/main.ts` 捕获阶段监听器里的一条分支，与 `Ctrl+Shift+K`（清屏）同级。**不是「键位绑定」**：`GLOSSARY.md` 里的「动作」「键位绑定」在代码里尚无注册表，文案里不得承诺「可在设置里改键」。

## 查找条

- **每分格一条**，浮在该分格右上角：条本身挂在终端宿主（`view.hostEl`）里，绝对定位、不占布局，因此布局重建、滑动分隔条、甚至拖格都不会让它错位或消失。
- 切走焦点：隐藏、状态（查询、两个开关、当前命中序号）按分格保留；切回还原。
- 打开时输入框拿焦点，并登记进 `blocksOwnershipFocus()`，与历史浮层、三个模态同级；状态点显示「查找条持有按键」。
- 关闭后焦点回输入条（若当前输入所有权属输入条），否则回终端。
- **直通模式下也能打开**，代价是那一刻按键不再进正在运行的程序。这是用户显式请求查找的结果，不是所有权判定的例外。
- `Ctrl+Shift+K`（清屏）时关闭查找条并清掉高亮；终端视图被 `dispose` 重建时同样清掉。

## 匹配规则

- **字面子串。** 不做正则、不做整词（见「尚未决定」）。
- **默认不区分大小写**，开关切到区分大小写。
- **循环查找默认开**：最后一个命中的「下一个」回到第 1 个，第一个命中的「上一个」跳到最后一个。关闭后到端点即停，并给出明确的「到头了」反馈而不是静默不动。

## 两个开关

| 开关 | 默认 | 记忆 |
|---|---|---|
| 区分大小写 | 关 | 应用级 |
| 循环查找 | 开 | 应用级 |

存在 `localStorage` 的 `pinshell.find`，与右栏顺序、面板高度、文件面板偏好同一套做法；**不进** Rust 的 `workspace.json`，那里只有项目、会话与布局比例。

与「检索」的心智差异是有意保留的：检索是一次性查一堆，用 smart case（输入里出现大写才区分）；查找是逐键增量，显式开关才可预期。

## 命中、计数与流动

- 全部命中高亮，当前命中加重；显示 `n/m`。
- 0 命中时输入框描红，计数显示 `0/0`。
- **高亮上限 1000 个命中**（插件 `highlightLimit` 的默认值）。超过之后计数停在 1000，「下一个」也只在这 1000 个里走。这是插件的上限，不是我们的选择。
- 查找打开期间会话仍在输出：插件自己监听 `onWriteParsed`，输出停下约 200ms 后重扫一遍并尽量保持当前命中的位置；连续刷屏时这个去抖一直不触发，只在停顿后算一次。前端不另加节流。
- 当前命中**按序号维持**，不做按文本位置的维持——输出刷屏时那会让高亮看起来粘在固定坐标上。
- 命中被新输出挤出卷轴（5000 行）即消失，不提示、不报警。

## 容量与数据源

- 前端 xterm 缓冲区，`SCROLLBACK_LINES = 5000` 行（`src/main.ts` 的常量，约 2 MB/会话）。更早的输出在 xterm 里已经被裁掉，查找看不到，也没有别的通路能补上。
- 备用屏：查找作用于当前活动的 buffer，即全屏程序自己那块屏幕；退出备用屏后高亮不保留。

## 实现落点

| 事项 | 位置 |
|---|---|
| 查找插件 | `@xterm/addon-search@0.16`（配 xterm 6），在 `TerminalPool.create()` 里 `loadAddon`，挂在 `TerminalView.search` 上；`allowProposedApi` 已开（装饰器需要） |
| 键位分支 | `src/main.ts` 捕获阶段监听器的 `Ctrl+Shift+*` 链，与清屏、暂停同级 |
| 纯逻辑 | `src/findBar.ts`：偏好读写、命中序号换算、到头判定（`canStep`） |
| DOM 与插件调用 | `src/findBarUi.ts`：每分格一个查找条（挂在 `view.hostEl` 里）、输入去抖、循环闸门、命中事件 |
| 焦点互斥 | `blocksOwnershipFocus()` 加入「查找条拿着键盘焦点」 |
| 状态点 | 查找条拿着焦点时 `#own-dot` 显示蓝点并带提示 |
| 文案 | `src/i18n.ts` 的 `find.*` 中英条目（本仓库要求一条不缺） |
| 样式 | `src/styles.css` 的 `.find-bar` 一节，颜色全部取自主题变量 |
| 右栏 | **不改**。`rightBar.ts`、`index.html` 的面板骨架、`globalSettingsUi` 的显隐排序都不动 |

## 测试

1. **L0 单测**（`src/findBar.test.ts`，随 `npm test` 跑，属常跑集）：偏好读写、命中序号换算、到头判定，以及一条插件契约断言（`findNext` / `findPrevious` / `clearDecorations` / `onDidChangeResults` 仍然存在）。
2. **查找条状态机**（`src/findBarUi.test.ts`，happy-dom + 桩插件）：打开/关闭/焦点归属、输入去抖、循环闸门、0 命中描红、分格隔离与切回还原、清屏关闭、视图销毁后不留旧查询。桩插件只模拟三条真正要紧的语义：同一查询换位置、换查询回到第一个、`clearDecorations` 把缓存一起清掉。
3. **插件的真实行为**（`src/findBarAddon.test.ts`，happy-dom + 真 xterm + 真插件）：大小写的三种组合（不敏感 / 敏感的小写查询 / 敏感的大写查询）、`findNext` 与 `findPrevious` 的绕回、跨折点的子串能命中且只算一个。
   - 前提是**必须有 DOM 并 `open()`**。纯 Node 里 xterm 没有 selection service，插件内部的 `select()` 会直接抛 `TypeError: Cannot read properties of undefined (reading 'setSelection')`——`scripts/bench-scrollback.mjs` 那种跑法只验证得了「解析 + 缓冲」，验证不了查找。
   - 这两条 DOM 用例要拉真实 xterm（含各自的 DOM 环境），比纯逻辑慢一个量级，但仍在一秒级；它们是第三方行为的看门狗，插件升级时先红。
4. **手工**（`npm run app:dev`）：直通模式下打开查找条、备用屏（vim / htop）里查找、串口会话查找、清屏后查找条关闭、二分格各自的高亮、输出持续流动时计数跟着变而当前高亮不跳到别的行、主题切换后高亮配色跟着换。

## 尚未决定

1. **整词匹配**：是否加第三个开关。
2. **正则**：一旦开放，用户会把 ANSI 与控制序列当 bug 报上来，需要先明确「匹配的是屏幕文本，不是字节流」。
3. **跨会话 / 冷会话检索**：属于第二阶段的「搜索」，需要先复审 ADR 0009，并回答「结果列表怎么排序、跨项目怎么分组、点击后是否自动拉起」。
4. **命中列表**：是否把结果做成右栏第 4 个面板（当前是每分格浮层，两套形态的入口语义会打架）。
