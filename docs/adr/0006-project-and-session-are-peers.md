# 0006 项目与会话是两套并列的对象

- 状态：**部分被 ADR 0008 取代**（2026-11-22）——项目不再是与会话并列的对象，而是会话的唯一容器；「独立会话」「展示模式」已删除。本 ADR 保留作为当时的决策记录。
- 相关：ADR 0001、ADR 0004、ADR 0008、GLOSSARY「项目」「归属」「分格」

## 背景

需求要新增「项目」：一个项目拥有若干会话（pwsh、串口、cmd、Git Bash），并把这些会话按 2×2 这类形状同时显示。现有的产品形态是「一切以会话为主」——侧栏一个平铺列表，主区同时只显示一个会话。

最直觉的做法是让会话升级成项目成员：项目是会话的分组，把会话拖进去、拖出来，两个视图看同一批会话。产品要求否掉了这条路：**项目和会话是隔离的对象，没有任何联系**——项目自己拥有会话，那些会话不进会话列表，独立会话也拖不进项目。

## 决策

1. **并列，不互通。** 项目拥有会话；独立会话不属于任何项目。项目里的会话不出现在会话列表、不参与会话的批量操作，也不能被拖出项目；反之亦然。跨两侧的移动一律不做。
2. **同一套机制，只多一个归属。** 项目会话就是会话：同一个 `SessionMeta`、同一个 Transport、同一份 `history.db`、同一个 `scrollback/` 目录、同一套输入所有权判定，并且仍然遵守「同一串口不允许两个热会话」。区别只有 `owner`（空 = 独立会话，或某个项目）。
3. **项目取代窗口成为视图容器。** `Layout`（二叉分格树，最深 3 层、比例 0.1–0.9）归项目所有；`Window` / `Rect` / `windows[]` 这层从未接线，退役删除。本版仍然只开一个操作系统窗口，跨窗口吸附继续不做。
4. **组合只靠拖拽。** 拖到分格边缘 = 在那一侧切一格；拖到中心 = 两格交换（替换会悄悄关掉一个会话，代价太高）；拖出项目 = 关闭那个会话；拖分隔线 = 改比例；从新建面板拖一条 profile 进来 = 创建一个会话。不做网格预设按钮。
5. **激活时终端全起、串口保持冷。** 打开项目把它全部终端会话拉成热会话；串口格子只是占位，点那一格才连端口——自动连会从别的程序手里抢走 COM 口。离开项目不结束任何进程。被显式冻结过的项目是例外：再次打开时全部格子保持冷（可以看卷轴快照），点哪格拉哪格，另给一个「全部启动」，否则冻结等于没做。
6. **收尾分两级，破坏性动作必须显式。** 关掉一个格子只结束运行时：格子留在原处变冷（灰显、点它重新拉起），布局不重排，历史与卷轴快照都保留——进程自己退出走的也是这条路。移除这一格才是销毁那个会话，历史与快照一起删，二次确认。项目层面同理：冻结项目写快照、结束进程、释放串口、保留布局与记录，下次打开原样恢复；删除项目连会话、历史、快照一起销毁，二次确认。移除最后一格后项目留作空壳，不自动消失。
7. **侧栏用模式开关，主区跟随。** 项目模式列项目（可展开看它拥有的会话），会话模式就是今天的平铺列表；主区同一时刻只展示一侧。「会话模式」因此与今天完全同形，项目功能不改变老用户的任何操作。

## 后果

- 主区第一次需要**同时存在多个 xterm 实例**。现在 `main.ts` 是一个 `term` 单例加一份全局 `sessionId`，切会话靠 `term.reset()` + 整屏重放；这套单例必须先拆成「每会话一套终端 + 一份焦点状态」，这是本次改动的主要成本。
- 输入条仍然一条：它绑的是焦点分格的会话，非焦点分格直通。所有权判定依旧是「一个会话一份」，没有变成「一个项目一份」。
- 串口独占跨两侧成立，而且必须给得出原因：项目格子占着 `COM3` 时，独立会话开同一个口要明确报「被项目 A 的会话占用」，而不是静默失败。
- **「关格」与「移除格」必须是两个动词。** 折叠必然删掉会话元数据，历史就成了谁也读不到的孤儿；所以想保留历史，格子就得留在原地当冷格子。项目里没有「放回未分组」这个回收站，这是并列的直接代价。
- `session_tree` 仍然一次返回全部会话，多一个 `owner` 字段；隔离是展示规则，不是数据隔离。前端按模式分流，不加第二条 IPC。
- `workspace.json` 升 v3：`sessions[].owner` + `projects[]`，删掉 `windows[]`。当前未发布，不做 v2 迁移。
- ADR 0004 里「窗口是视图、分格属于窗口」的部分由本决策取代；「分格不区分通道类型」「跨窗口只吸附不融合」「交换而不是替换」三条继续有效。

## 替代方案

- **会话升级成项目成员（可拖入拖出、两侧共享同一份列表）**：最灵活，但同一个会话同时出现在两个视图，会让输入所有权、串口独占、快照归属全部退化成引用计数问题，而且「我关掉这一格，另一边的列表里它还在吗」没有好答案。
- **两套实体两套栈**：项目格子自己一套历史、快照、设置。隔离最彻底，但要重写 M0–M5，而且两套代码各自持有一份端口表，抢 `COM` 口是必然而不是意外。
- **一项目一操作系统窗口**：需要先做多窗口与跨窗口吸附，成本远高于本次需求。
