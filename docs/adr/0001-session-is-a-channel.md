# 0001 会话是通道，不是 Shell 进程

- 状态：已接受（2026-11-16）
- 相关：GLOSSARY「会话」「传输通道」

## 背景

需求里终端与串口要共处一个会话树，共享标题、快照还原、时间戳、一键清窗口。最直觉的建模是「会话 = 一个 shell 进程」，然后把串口当成外挂面板。

## 决策

**会话 = 一条被用户命名、可快照、可回放的 I/O 通道。** 通道类型（终端 / 串口）是可替换的传输实现，能力按位开放：

- 终端通道：补全、Ghost Text、命令历史、Ctrl+R、CWD 跟随
- 串口通道：发送历史、HEX 视图、帧格式/流控/DTR-RTS、日志
- 两者共有：标题、树节点、时间戳、一键清窗口、快照还原、命令片段

## 后果

- 会话生命周期状态机（冷 / 启动中 / 热 / 暂停 / 关闭）一套，两种通道复用。
- 快照结构必须对「没有 CWD 的会话」成立；串口会话的 CWD 字段为空。
- `Ctrl+R`、Ghost Text 这类入口必须按能力位隐藏，而不是按会话类型分支判断。
- 串口「暂停 = 真释放端口」与终端「关闭 = 结束进程」在语义上对齐了：都是**放弃资源、保留元数据**。

## 替代方案

- **会话 = shell 进程 + 串口作为独立面板**：改动最小，但串口就永远拿不到快照还原、时间戳、命令片段，等于两套产品拼在一起。
- **会话 = 标签页**：把 UI 概念当领域概念，一旦要做「一个会话出现在两个窗口」就崩。
