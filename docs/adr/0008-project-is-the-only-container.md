# 0008 项目是会话的唯一容器

- 状态：已接受（2026-11-22）
- 相关：ADR 0004、ADR 0006、ADR 0007、GLOSSARY「项目」「归属」「项目栏」「项目行 / 会话行」

## 背景

ADR 0006 让项目与会话并列：左栏用模式开关在「项目」与「会话」之间切换，独立会话走平铺列表与批量操作，项目会话走分格。两套形态各有各的入口，同一个动作在不同模式下行为不同；新建项目是一键生成默认名，新建会话是 profile 菜单，落点又是另一个前置弹窗，「先填信息再创建」这件事被拆成三段。左栏同时承载两种对象，收起/展开、批量选择、会话列表这些能力也都跟着两套形态各写一份。

需求把左栏重新划了一遍：左栏只放项目；项目行展开列出它拥有的会话；设置入口常驻在左栏底部；不再有整栏收起，改为项目的全收起/全展开；新建项目与新建会话都要先经过配置弹窗。

## 决策

1. **项目是唯一容器。** 每条会话都属于且只属于一个项目，`SessionMeta.owner` 是必填字段；「独立会话」这个概念从模型、后端路径与界面上一并删除。
2. **左栏固定为项目栏。** 删除项目/会话模式开关、独立会话列表与批量选择；左栏只画项目行与展开后的会话行。
3. **无主会话不迁移。** 加载旧工作区时，`owner` 缺失或为空的会话直接丢弃（连同其节点）；`workspace.json` 升 v4，会话的 `owner` 必填。不做「未分组」项目之类的自动收容。
4. **左栏整栏收起保留，入口归标题栏。** 标题栏左侧的「收起项目栏」按钮把整栏收成 26px 竖条；宽度拖动与双击恢复默认保留。
5. **全收起 / 全展开是项目栏头部两个独立按钮。** 没有展开中的项目时「全部收起」禁用，全部已收起时「全部展开」禁用；每个项目的展开状态存进 `localStorage`，重启保持，默认全展开。这是**项目行**的折叠，与整栏折叠无关。
6. **项目栏的整栏收起保留。** 标题栏左侧的按钮把整栏收成 26px 竖条（竖条上保留展开入口与设置齿轮）；宽度拖动与双击恢复默认不变。收起状态与宽度一起存进 `localStorage`。
7. **项目行的交互与功能栏行同构。** 整行单击（双击同理）展开/收起该项目并顺带选中；行尾常驻「＋新建会话」与「⋯」，「⋯」弹出的与右键菜单完全相同（全部启动 / 项目设置 / 冻结 / 删除），两个入口一份内容。
8. **新建项目与新建会话都要先填弹窗。** 项目栏顶部的 ＋ 只新建项目；项目行右侧的 ＋ 只新建该项目的会话；两者都不再「点一下就直接建」。
9. **会话弹窗合并原来的 profile 菜单与串口弹窗。** 传输方式（终端 / 串口）是第一个字段；终端的 shell profile 与起始目录、串口的端口与 8N1 参数都在同一个表单里填；落点（填第一格 / 向右切 / 向下切 / 替换当前格）也在这个弹窗里选，默认「向右切」，选中「替换当前格」时写明被替换会话的历史与快照会一起删除。
10. **放弃拖 profile 新建会话。** 落点菜单与 profile 菜单一起消失后，跨格拖动只保留已有的格子（交换 / 切分 / 移动）。
11. **设置入口保留两个，功能相同。** 项目栏底部的按钮常驻左下角（收起后只剩齿轮），与标题栏齿轮打开同一个全局设置弹窗。
12. **新建后的行为唯一。** 新建项目：选中、展开、主区显示空项目状态（带「新建会话」按钮），不连锁弹会话弹窗。新建会话：切到该项目、展开、预热终端格（串口保持冷）、焦点给新格、关闭弹窗。

## 后果

- 老用户升级后，独立会话、它们的节点与历史在界面上消失；`workspace.json` 里不再有 `owner: null`。降级回旧版本时，v4 文件会被判为不可读（版本比较是 `>`）。
- `sessionScope.ts`、`byMode`、`switchDisplayMode`、批量选择与 `close_session` / `add_session` 这类只为独立会话存在的代码一并删除，前后端不再有「会话可以没有项目」的分支。
- 项目栏的会话行是进入分格的唯一侧栏入口；主区与输入条的焦点仍由 `focusSessionId` 决定。
- 新建会话只有一条路径（弹窗），行为与错误提示（端口占用、目录不存在、深度超限）都集中在一个表单里。
- 左栏宽度与整栏折叠都是窗口级布局，`pinshell.sidebar` 同时存 `width` 与 `collapsed`。
- 项目栏头部需要常驻三个按钮（全部收起、全部展开、＋），窄栏下按现有 `panel-tools` 的换行规则排。
- 收起后的 26px 竖条上保留两个入口：竖排「项目」字样的展开按钮，以及只显示齿轮的设置按钮。

## 替代方案

- **保留会话模式与独立会话**：改动最小，但左栏永远有两个互斥形态，所有「在左栏做什么」的问题都要回答两遍；需求明确要求左栏固定为项目栏。
- **把无主会话收进自动创建的「未分组」项目**：不丢数据，但会凭空造一个用户没建过的项目，且要处理多项目切分、命名冲突；用户选择直接删除。
- **保留 profile 菜单并让每项再开弹窗**：能保住拖拽新建，但「先弹窗」变成「先菜单再弹窗」，与第 6 条冲突；拖拽新建是低频能力，代价不值得。
- **保留左栏整栏收起**：与「设置按钮常驻左下角」有张力（收起后左下角只剩齿轮），但整栏收起是老用户的既有习惯，保留它、让竖条继续承载设置入口，比删掉更好。
