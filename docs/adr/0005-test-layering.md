# 0005 测试分层：常跑集只到 L1，GUI 自动化不进常跑

- 状态：已接受（2026-11-16）
- 相关：`docs/testing.md`、`docs/research/04-osc-pwsh-probe.md`、GLOSSARY「常跑集」「红线」「隔离运行」

## 背景

单人开发，AI 在同一台机器上改代码，而用户经常边用电脑边让它干活。测试的第一约束不是覆盖率，而是**不能打断**：不弹窗、不抢焦点、不占开发端口、不抢构建锁。同时 `tauri dev` 常年开着，主 `target` 目录被占用、`pinshell.exe` 被进程锁住。

另有两条现实：这台机器没有装 `tauri-driver` 与匹配 WebView2 的 `msedgedriver`；产品最关键的判定（输入归属）恰好是纯逻辑，不需要 GUI 也能测。

## 决策

1. **四层**：L0 纯逻辑 / L1 集成 / L2 契约 / L3 端到端与性能。**常跑集 = L0 + L2**，必须秒级、无窗口、不占构建锁。
2. **纯逻辑进独立 crate**（`src-tauri/core-domain`）：零依赖、自有 target 目录，因此在 `tauri dev` 跑着的时候也能测。
3. **L1 用真 PTY 但不起 GUI**：与主 target 共用编译产物，所以只在 dev 未运行时跑；由闸门脚本判断并拒绝，不靠人记得。
4. **L3 永不进常跑**：它会开真实窗口、抢焦点。只保留手工验收清单与性能采集，且性能门禁只在 release 构建、人离开时跑。
5. **门禁落在本地 pre-push**（L0，≤10 秒），暂不上 CI。
6. **测试不得**按进程名杀进程、写用户 profile、绑开发端口、碰真实数据目录。

## 后果

- 没有跨机器回归网：别人的机器上坏了不会自动发现，靠发布前的手工清单兜底。
- 输入归属、解析、状态机得到持续保护；UI 布局、IME、字体回退、高 DPI 只能手验。
- 将来要加 CI 时，L0 可以直接搬（独立 crate、无平台依赖）；L1 需要 Windows runner；L3 不建议自动化。
- 每次 push 多出约一秒的等待，换来「输入判定不会被顺手改坏」。

## 替代方案

- **全量 CI + tauri-driver E2E**：回归网最厚，但每次运行都会抢焦点，Windows runner 慢且贵，单人项目维护不过来。
- **只写手工清单**：零成本，但「按错键打进错误进程」这类问题的代价太高，靠人眼长期守不住。
- **等有第二个人再分层**：短期省事，但先写下的判定逻辑会先长出两套语义，再拆成本更高。
