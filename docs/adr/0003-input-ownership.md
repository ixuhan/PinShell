# 0003 输入所有权协议

- 状态：已接受（2026-11-16）
- 相关：GLOSSARY「输入所有权」「提示符就绪」「集成脚本」

## 背景

输入条独占键盘，因此必须精确知道「何时让位」。可选信号里没有任何一个是完备的：备用屏只覆盖全屏程序，提示符标记要靠注入脚本，ConPTY 也不提供任何子进程状态查询。所以协议必须承认「不知道」是一种合法状态。

## 决策

### 一、所有权按通道类型判定

| 通道 | 所有权规则 |
|---|---|
| 终端 | 备用屏 > 提示符就绪 > 未知。仅「提示符就绪」归输入条 |
| 串口 | 恒归输入条（不存在第二个消费按键的进程） |

### 二、终端状态机

```
Unknown ──133;A──► Prompt ──133;C──► Running ──133;D──► Prompt
   │                 │                  │
   │                 └──1049h────────► AltScreen ──1049l──► Unknown
   └─静默+行首──► PromptGuess（只驱动提示，不参与所有权）
```

- `Unknown`：没收到任何标记。按键全透传，输入条显示为「建议模式」。
- `Prompt`：收到 `A` 且此后未收到 `C`。输入条接管。
- `Running`：收到 `C`；或用户回车后 N 毫秒内未收到新 `A`。按键全透传。
- `AltScreen`：优先级最高，强制透传；退出后回 `Unknown`，不回 `Prompt`（无法知道是谁退出的）。

### 三、集成脚本的注入方式

默认只对**我们自己启动的进程**注入（PowerShell 用 `-NoExit -Command ". <path>"`，bash 用 `--init-file <path> -i`），**不写用户 profile、不写注册表 AutoRun**。设置页提供一个可选按钮把一行 `source` 追加到用户 profile（默认关闭）。

bash 不用 `BASH_ENV`：它只对非交互 shell 生效，交互 shell 看不到。`--init-file` 会顶掉默认启动文件，所以脚本自己先读 `/etc/profile` 与 `~/.bashrc`，再把标记包进 `PS1`/`PS0`（用 `\[ \]` 保证 readline 不把标记算进宽度）。

理由：默认零侵入；一旦改用户 dotfiles，卸载后残留会让用户困惑，而且与「便携目录拷走即迁移」冲突。

### 四、cmd 的降级

cmd 无原生钩子，只能靠 `PROMPT` 环境变量拼标记，且拿不到退出码。降级顺序：`PROMPT` 注入成功 → 视为 `Prompt`/`Running` 可用但无退出码；注入失败 → 等同「未装集成脚本」，且 `cmd /c`、`pause` 一律视为 `Running`。

### 五、UI 约定

- 三色状态点：绿 = 确知就绪；琥珀 = 猜测；灰 = 直通/未知。
- 猜测状态下输入条只做建议，按键仍透传；用户可快捷键**显式锁定**接管（锁定后即使状态机说 Running 也不交还，直到用户再次切换）。
- 状态点必须常驻可见，不能只在悬停时显示。
- 焦点随裁定搬动：`input_bar` 时在输入条，否则在终端。前端不拦截按键再做二次判断——两边都判一次就等于两套规则。

## 不可解场景与产品对策

| 场景 | 症状 | 对策 |
|---|---|---|
| 密码提示（ssh/sudo） | 无 `C/D`，会被判成 Prompt | 进入 `Prompt` 后若首个输出没有 `C` 且出现「模糊匹配密码类提示」，自动转 `Running` 并提示可锁定 |
| `pause` / `set /p` / `read` | 状态是 Running，但程序在等输入 | 用户按 `Ctrl+Shift+P` 切直通；不做自动猜测 |
| REPL（python/node） | 有 `C` 永远没有 `D` | 保持 Running；REPL 内部输入由直通承担 |
| `git commit` 打开编辑器 | `D` 被推迟到编辑器退出 | 备用屏优先，退出后回 Unknown |
| 静默构建 | 超时启发式误判 | 猜测永不抢键，误判只影响状态点颜色 |
| tmux/screen 未开 passthrough | 标记被吞 | 文档提示开启 `allow-passthrough` |

## 后果

- 未装集成脚本的会话可用但降级：输入条存在、不能接管，产品必须显式告知原因并提供修复入口。
- 状态机的错误只影响「提示质量」，不影响「键盘能不能用」——这是把未知当一等状态的直接收益。
- 需要在 M1 就把集成脚本与状态机一起做，不能先做输入条再补判定。

## 替代方案

- **只靠备用屏 + 超时**：实现最省，但密码提示与静默构建会稳定误判，等于拿用户键盘冒险。
- **让 Shell 一直开着行编辑，输入条只当记事本**：放弃产品核心差异点。
- **改用户 profile 自动注入**：覆盖率最高，但侵入性强，与便携定位冲突。
