# 0009 查找只作用于前端缓冲区

- 状态：已接受（2026-11-24）
- 相关：ADR 0003、GLOSSARY「查找」「检索」「卷轴快照」「回放缓冲」「冷会话」

## 背景

同一个会话的输出在项目里存在三份副本，能力各不相同：

- **前端 xterm 缓冲区**：最新、永远与屏幕一致，但只保留最近 5000 行（`SCROLLBACK_LINES`，约 2 MB/会话），进程消失即消失。
- **卷轴快照** `scrollback/<id>.ansi`：带 ANSI 的裸文本，由 256 KB 的回放缓冲生成，空闲 3 秒即刷新，冷会话也有；但它是「最后一次刷盘时的画面」，不是实时的，且在清屏时被删除。
- **会话日志**：默认关闭，目录与文件名由用户自选，默认模板不含会话 id，多个会话共用一个目录时无法反查归属；没有大小上限、没有轮转、没有保留策略。

需求是「新增会话内容的搜索功能」。第一版必须回答：搜哪一份。

## 决策

**查找只作用于前端 xterm 缓冲区，不读磁盘上的任何副本。**

1. 查找的语义绑定「已经画出来的东西」：命中即高亮、跳转即滚动，与屏幕严格一致。
2. 冷会话不提供查找入口。它没有 Terminal 实例，要搜必须先拉起；想不拉起就搜，只能等第二阶段的磁盘检索。
3. 更早的输出（超出 5000 行）搜不到。这是边界，不是缺陷：补上它就要引入索引，那是另一个功能。

## 后果

- 查找永远不需要 IO，不需要索引，不依赖日志开关，也不与后端共享状态；`Ctrl+Shift+F` 的响应与屏幕刷新同源。
- 想搜昨天那个会话、想跨会话搜同一段输出，这一版都做不到。用户会提出这个需求，届时必须先复审本 ADR，而不是在查找里悄悄加一条读文件的路径。
- 清屏会立即使查找无内容可搜（快照被删、缓冲区被清），这与「一键清窗口只动显示层」的既有语义一致。

## 替代方案

- **读卷轴快照做磁盘检索**：能覆盖冷会话且不需要拉起进程，但快照落后于屏幕（最多数秒到整场会话），会出现「屏幕上明明有、查找说没有」的错位；`.ansi` 里混着 ANSI 转义与「上次会话结束于此」分隔线，匹配前必须剥离，命中位置也无法对应到可见行列。
- **索引会话日志**：能拿到完整历史，但日志默认关闭、目录与文件名无法反查会话归属，要先改默认模板与归属机制——那是另一个产品决策，不该被「加个查找」顺带做掉。
- **后端实时全文索引**：能力最完整，但要为每条热会话维护索引、处理清屏与截断的一致性问题，与「轻量、低内存」的产品定位直接冲突。
